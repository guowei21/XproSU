# 6.1.57 ↔ 6.1.145 ↔ 6.1.124 偏移对比报告

数据源（均为真机验证或本机内核实测）：
- `offsets-import-r15-6.1.57+6.1.145.json`：57 与 145 两条真机验证条目
- `scripts/sym_6157.txt`：57 内核完整 kallsyms（ksg.py 从设备自身 Image 解出，109631 符号）
- `<workspace>/bootimg/kallsyms_manual.txt`：本机 6.1.124 内核 kallsyms（112084 符号，base=0xffffffc008000000）
- 引擎自身解析器 `offsets_json.c`（宿主编译实测三份 JSON 均解析正确）

## 一、57 → 145 之间到底改了什么

### 头部标量（loader 实际解析的 4 项）—— 零改动

| 字段 | 6.1.57 | 6.1.145 | 结论 |
|---|---|---|---|
| kernel_phys_load | 0x80000000 | 0x80000000 | 不变 |
| pselect_waiter_shift | 1 | 1 | 不变 |
| compact_waiter | 1 | 1 | 不变 |
| mm_struct_sz | 1024 | 1024 | 不变 |
| btf_size / kimage_text_base | （57 缺 btf_size） | 5836866 / 0xffffffc008000000 | loader 根本不读这两项 |

### struct_fields（34 键）—— 零改动

33 个有效键值全部相同（cred/seccomp/page/slab/task_*/waiter_*）。
其中 loader 实际解析 15 个 `task_*` 键；其余（cred_*、waiter_* 等）被引擎忽略。

### symbols（11 项）—— 全部改动

| 键 | 57 值 | 145 值 | 漂移 | 语义（57 工程钉死） |
|---|---|---|---|---|
| off_init_task | 0x205f0c0 | 0x210fb40 | +0xb0a80 | init_task |
| off_init_cred | 0x2072f10 | 0x2122430 | +0xaf520 | init_cred |
| off_root_task_group | 0x2285700 | 0x234a740 | +0xc5040 | root_task_group |
| off_selinux_enforcing | 0x23b8588 | 0x247fb98 | +0xc7610 | **selinux_state**（enforcing@struct+0） |
| off_selinux_blob_sizes | 0x15d1050 | 0x16333e0 | +0x62390 | selinux_blob_sizes |
| off_security_hook_heads | 0x15d0948 | 0x1632cd0 | +0x62388 | security_hook_heads |
| off_tp_sys_exit_tp | 0x22320a0 | 0x22f3600 | +0xc1560 | __tracepoint_sys_exit |
| off_tp_sys_exit_funcs | 0x22320e0 | 0x22f3640 | +0xc1560 | tp + 0x40（6.1 布局） |
| off_slide_nfulnl_logger | 0x2052cd8 | 0x2102f00 | +0xb0228 | nfulnl_logger |
| off_slide_loggers_0_1 | 0x2052c28 | 0x22d4e28 | +0x282200 | loggers[0][1]（loggers+8） |
| off_slide_boot_id | 0x23d9910 | 0x2276810 | **-0x163100** | sysctl_bootid |

每个 57 值都经 `sym_6157.txt` 逐一对号（10 个 EXACT 命中，loggers_0_1=loggers+0x8、funcs=tp+0x40 属结构内偏移，非独立符号）。

**关键观察：漂移不是常数。** rodata 区（hook_heads/blob_sizes）+0x62390、data 区（init_task/cred/logger）≈+0xb0000、bss 区（root_tg/enforcing）+0xc5000~0xc7600、boot_id 甚至反向 -0x163100。⇒ 跨内核版本**不可能**用统一 delta 或"沿用旧符号"适配，必须从目标内核自己的 kallsyms 逐符号重提。

## 二、124 与 57 的同源性交叉验证（同一台机器的新旧固件）

| 内部间距指纹 | 6.1.57 | 6.1.124 | 含义 |
|---|---|---|---|
| loggers[0][1] − nfulnl_logger | −0xb0 | **−0xb0** | 相邻布局，同源 ✓ |
| sysctl_bootid − selinux_state | +0x21388 | **+0x21610** | 同区布局，同源 ✓ |
| tp_funcs − tp | +0x40 | **+0x40** | 6.1 KMI 一致 ✓ |
| init_cred − init_task | +0x13e50 | +0x128f0 | 每版不同（正常） |
| blob_sizes − hook_heads | +0x708 | +0x710 | 每版不同（正常） |

124 的 9 个符号值全部由本机 kallsyms EXACT 提取，语义与 57 工程一一对应——方法与产出"真机验证的 57 条目"完全相同。

## 三、v2 修正了旧版 JSON 的什么

| 项 | 旧 offsets-6.1.124-local.json | v2 |
|---|---|---|
| off_tp_sys_exit_tp / funcs | **缺失**（引擎以 0 运行 → VR 阶段必失败，ksud 会被 vr.ko 杀） | 0x22d19c0 / 0x22d1a00（=__tracepoint_sys_exit+0x40，kallsyms EXACT） |
| struct_fields 多余键 cred_caps_offset | 有（loader 忽略，无害） | 已去除，33 键与真机模板一致 |
| 9 个符号值 | 已 EXACT | 不变（本就对） |

引擎自身解析器实测：v2 全部 11 符号 + 4 标量正确载入。

## 四、"改偏移变量导致卡住"的归因核查

运行日志卡点：`mcast route seq=16+ … calls 递增、success 恒 0`。
- `calls` 递增 = arm(≥16) 后 consumer 每轮发起了 punch（sched_setattr/futex PI walk）；
- `success=0` = PI walk 从未完成；
- 该 walk 依赖：struct_fields（与真机验证条目逐值相同）+ 引擎内部 futex_hash/竞态时序。
- **9 个符号值在 walk 完成之前根本不被使用**（它们只决定 walk 成功后"写往哪"）。卡点发生在所有被改字段的上游。
- 若按"不改符号"沿用 145 值：selinux_enforcing 会偏 +0x22b98（写到 sysctl_bootid 之后的未知 bss），W1 verify 永远失败。不存在"不改符号也能跑通"的选项。

另：README §2 明确 off_slide_* 三项**只出现在日志打印**（源码 grep 复核：仅 util.c:168-172 与 AUDIT 行引用），改错也不影响功能。

## 五、本次最重要的发现：设备上跑的引擎不是这份 R15 源码

运行日志含以下字符串，**R15 源码与 dist/libghostlock-r15-arm64.so（sha256=d9ff9c43… 与 README 一致）中均不存在**：
- `ksud ready`
- `exp: futex-direct-punch enabled (sched_setattr punch skipped)`
- `W1: SELinux attempt 1/15 slide +0x80000`（R15 无 slide 机制；其 W1 目标=data_addr(off)，本例应为 0xffffff800245d000，日志却是 +0x80000 的 0xffffff80024dd000）

而 AUDIT 内建列与 target.h 完全吻合、mcast 日志格式与 fops.c 一致 → 运行的是**同代码库的更新分支**（R16/R17 或后续），不是所提供的 R15。其两处差异正踩在要害上：
1. `futex-direct-punch` 跳过了 sched_setattr punch——R15 源码注释明言 *"(calls%19)+1 is what makes sched_setattr succeed on 6.1 compact"*；
2. W1 的 slide +0x80000 机制无源码可查（57 真机条目 delta=0 无 slide 也跑通过）。
